## 先卖清晰的服务，不扩张系统范围

第一阶段面向已经在同一个 OJ 使用的合作教练和机构，提供 CSP 复赛模拟的托管服务：管理员负责部署与运维，老师在 OJ 建赛、审核材料和办赛，学生使用统一 Linux 桌面并网页递交。其他地区可按题使用目录兜底。暂不新增支付、商城、独立机构后台或未经隔离验证的多租户产品。

AI 可以帮助准备题面、辅助数据和诊断，但比赛的登录、收代码、评测回传、截止与归档不能依赖 AI 在线操作。材料仍需教师审核；辅助数据不计入正式评测。

## 不变的交付承诺

1. OJ 是身份、比赛时间、源码、评测记录与成绩的唯一权威来源，不为了修复桌面问题改写 OJ 成绩或已有记录。
2. 优先级按“学生 × 题目”计算：最后一次成功接收的网页代码优先；该题没有网页递交时才读取截止目录。不是最高分优先，也不是先交网页后再让目录覆盖。
3. 已接收和已送达 OJ 是两个状态。回执明确显示时间、字节数、代码内容与送评状态；不以 URL 参数充当成功证据。
4. 截止后 30 分钟是核验、送评等待和归档时间，不是额外答题时间。已成功接收请求的同内容重试只取回旧回执，不接收新答案。
5. 活动比赛期间不升级；NOI Linux 故障不重启普通 OJ，不删除学生文件或比赛记录。

## 2026-09-09 三轮改进摘要

每轮都先检查实现和现象，补出失败用例，再修复并复测；不是把同一命令重复三次。

| 轮次 | 新发现 | 改进与回归范围 |
| --- | --- | --- |
| 第一轮 | 新安装可能漏配线程/进程限额，或继续使用已出过问题的 512 上限 | 默认 1024，配置启动前校验 1024～65536 的整数范围；回归配置、递交、送评与座位创建 |
| 第二轮 | 截止前接收成功但响应丢失时，HTTP 层阻止截止后的原请求回执查询 | 仅放行已知 nonce 至原子校验，同身份同源码返回原回执；拒绝新请求、变更源码和跨学生复用，保证不重复送评、不覆盖更新记录 |
| 第三轮 | 回执列表不自动跟随送评状态，成功参数可产生误导，异常核对提示不完整 | 用不含源码或分数的版本标记刷新回执列表；上传表单、隐藏页面与断网时不误刷新；成功提示须有真实接收记录，补齐待核对说明 |

测试数字和线上验证属于某次运行证据，不应长期当成产品能力指标。正式交付必须记录版本、日期、配置与结果，不能只引用本页描述。

## 后续改进：第四轮加密桌面候选

新增可选原生 HTTPS/WSS 直连，复用现有比赛机 Nginx，不增加代理组件。包含域名/EIP 与证书预检查、加密页面和 WebSocket 双检查、443 受管入站生命周期、关闭 TLS 模式的明文回退通道，以及递交代理对外部 HTTPS 证书的验证。默认关闭，原有部署不会被自动切换。

测试覆盖真实回环 TLS 握手、SNI/域名、信任链、有效期、WebSocket 拒绝和旧版 HTTP 兼容；这不等于真实桌面或公网证书已验收。启用条件和未完成的实机验证见 [加密桌面入口](DESKTOP_TLS.md)。容量与真人体验门槛不因本轮代码完成而自动通过。

## 后续改进：第五轮输入行为候选

键盘补丁从“只检查生成文字”补到实际 JavaScript 事件执行。修复旧 class 形式 noVNC 缺少 AltGr 中断函数时的点击错误，覆盖待处理 Ctrl 定时器、保留正常组合点击、过期修饰键释放、小键盘与旧补丁迁移；官方 legacy 分支保持原行为。未知源码先完整检查再写入，避免检查失败留下半套补丁。

noVNC 1.0/1.2 上游键盘模块离线事件检查已完成，但浏览器、IBus、GNOME、Geany 的实际链路仍待真人验收。新版桌面说明明确区分本机/远程输入法和文件输出；可按 [学生桌面日常体验验收](DESKTOP_ACCEPTANCE.md) 留档。候选键盘镜像标签为 `numpad-and-stale-modifier-v2`；该轮没有重建或切换线上桌面，后续实机检查见下一节。

## 后续改进：第七轮加密容量链路

容量工具新增 `direct_https` 原生加密档位，绑定专用域名、实际比赛机 IPv4 和 15 个不同座位。
浏览器对端检查、逐座 WSS 计数、TLS RTT、签名接收和只读探针使用同一冻结档位，拒绝旧 HTTP 或兼容代理
数据混入。旧 HTTP 配置与摘要保持兼容，不会自动升级现有站点。新增真实 TLS 请求和签名测试纳入现有
源码 CI 门禁；它们不启动真实学生浏览器，也不替代公网证书、60 分钟容量和合作教练独立办赛验收。
具体设置见 [容量验收说明](../deploy/V1_CAPACITY_REHEARSAL.md)。

## 后续改进：第八轮递交顺序保护

修复“较早网页递交进入待核对后，后续同题版本仍能越过它送评”的队列缺口。待核对不等于确定失败；
按比赛、学生、题目锁住这一条送评队列，后续源文件继续保存，精确核对成功后再按原顺序送评。
其他学生、题目与比赛不受影响，重启后约束仍保留。收卷遇到同题前序待核对时立即给出明确原因，
不等待到超时后误报、不自动重放旧代码，也不使用目录替换网页版本。本轮源码测试不代替最终 OJ 成绩核对。

同轮修复回执恢复误写成绩：已经评测的记录在恢复时不再调用缺省参数的比赛成绩初始化接口。
必须先核对 OJ 源记录与比赛成绩记录中的 RID、题目、状态和分数；两边尚未一致时继续等待。
旧版已知 RID 的恢复也不能重建或清零已有比赛记录。恢复保留原有递交计数补记流程，但不写回评测结果。
