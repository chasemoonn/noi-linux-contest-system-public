# 学生桌面日常体验验收

本页供管理员和参与试点的教练使用。一次约 10 分钟，必须在最终候选镜像、真实学生浏览器和单独测试账号上操作；自动测试不能代填“通过”。这不是 15 人容量验收。

## 准备与记录

管理员先确认没有真实活动比赛，再提供隔离测试赛、测试账号和入口。记录日期、候选提交与桌面镜像摘要、操作者、本机系统及浏览器版本、输入法、是否外接小键盘、网络类型。用户名和密码仅通过既有私信/私下渠道给本人，不粘进验收报告。原 OJ 和学生代码不作为故障注入对象。

本机先切为英文输入法；中文在远程桌面中切换。点击远程右上角语言标识确认当前语言，需要时用已配置的 `Ctrl+Space` 切换，不要无论当前状态都先按一次。

## 必测动作

| 动作 | 合格现象 | 记录 |
| --- | --- | --- |
| 开始答题 | 桌面“开始答题”打开每题唯一的正式 `.cpp`，能保存，不要求学生自己猜目录 | 未测试 / 通过 / 失败及现象 |
| 英文代码与缩进 | 在 Geany 输入 `int student_score = 0;`，下划线、括号正确；Tab 和 Shift+Tab 按编辑器设置缩进/取消缩进 | 未测试 / 通过 / 失败及现象 |
| 小键盘 | 数字 0～9、点、加减乘除和 Enter 能输入；记录本机 NumLock 状态。当前比赛补丁将数字区归一化为数字，不将其当作导航区 | 未测试 / 通过 / 失败及现象 |
| 选择与取消 | 按住 Shift 点击能范围选择；松开 Shift 后普通点击恢复光标；Ctrl 点击不能因补丁被错误取消 | 未测试 / 通过 / 失败及现象 |
| 中文注释 | 在远程选择中文输入，连续输入并修改三句注释；切回英文后可继续写代码，没有莫名替换或持续选中 | 未测试 / 通过 / 失败及现象 |

| 离开窗口再回来 | 正常保存后切到本机其他窗口再返回，普通点击与输入正常；不丢已保存文件。重连只关闭桌面连接标签，不关比赛主机 | 未测试 / 通过 / 失败及现象 |
| 网页递交 | 桌面 Firefox 打开回收系统、登录并选 `.cpp` 递交；回执内容、时间与版本正确，随后 OJ 确有对应记录 | 未测试 / 通过 / 失败及现象 |

若快捷键被本机拦截，先记录本机和浏览器，再用远程桌面菜单/工具栏完成同一操作，不能直接把快捷键兼容项标为通过。网络断开、页面能打开、WebSocket 已连接和实际输入顺畅是不同事实，分别记录。

## 出现问题时

- 松开 Shift 后仍整段选中：分别按一下左右 Shift 并松开，再普通点击；记录能否恢复。不要通过删代码退出选择。
- Geany 看起来“没运行”：先看编译信息，确认不是编译失败；文件读写题检查题目目录 `.in` 是否存在、`.out` 是否更新，不只看终端是否有文字。不要把保存当成编译或递交。
- 中文断续：确认本机没有同时进行中文候选输入；记录远程语言标识、在哪个应用中发生、切回英文是否正常。不能只因为输入法进程存在就判合格。
- 提交结果不明：保留回执和待核对状态，请老师按 OJ 记录处理；不要反复点不同入口、不覆盖已有版本、不重判真实成绩。
- 证书警告：停止访问并联系管理员，不能忽略警告来完成加密验收。

失败记录至少包含“操作顺序、预期、实际、恢复办法是否有效”。截图先遮挡密码、有效入口、学生身份及源码。修复后重做该动作及其前后相邻动作，不只测试故障消失的一瞬间。

## 当前自动测试覆盖的边界

镜像验收脚本会以隔离测试学生 `CSP001` 的权限，读取镜像里的 Geany C++ 命令，分别实际执行“编译”和“构建”，运行文件读写程序并与辅助 `.out` 对照，再通过正式目录收取程序核对源码字节和 SHA。测试只写自己创建的临时座位，不提交到 OJ；这不等同于实际按下 GUI 的 F5，也不能验证中文输入手感。

默认按配置模板的每座位 2560 MiB、1.5 CPU、1024 PID 和 1 GiB 共享内存验收。已有部署若资源较小，管理员应在没有活动比赛并持有部署锁时，按实际限制另做验收，例如：

```bash
NOI_VERIFY_MEMORY_MIB=1536 NOI_VERIFY_CPUS=1.0 \
  bash deploy/verify-contest-image-local.sh '<候选镜像不可变 ID>' '<对应 40 位源码提交>'
```

记录中必须同时保留镜像 ID、资源档位和结果。单座位编译、运行、登录状态与重启保留检查通过，也不能代替 15 人加 2 个备用位的持续容量验收。

键盘补丁自动测试会执行生成的 JavaScript，覆盖过期修饰键释放、保留正常 Shift/Ctrl/Alt/Meta 点击、Ctrl/AltGr 延迟定时器、小键盘映射、旧补丁升级与未知源码不部分改写。独立离线检查还对 noVNC 上游 1.0/1.2 的键盘模块执行事件序列；不代表所有 noVNC 版本都已支持，更不代表浏览器、IBus、GNOME 和 Geany 的整条实机链路已经验收。

较早补丁对 class 形式键盘直接调用 `_interruptAltGrSequence()`，但 noVNC 1.2 没有这个方法。新版先检查方法是否存在，旧 class 分支取消待处理定时器并按当前 Ctrl 状态处理，legacy 分支保持原行为。依据：[noVNC 1.2 键盘实现](https://github.com/novnc/noVNC/blob/v1.2.0/core/input/keyboard.js)、[noVNC 1.0 键盘实现](https://github.com/novnc/noVNC/blob/v1.0.0/core/input/keyboard.js)。

桌面镜像候选须使用键盘补丁标签 `numpad-and-stale-modifier-v2` 并完成已有镜像验收后再提升。不能热改正在比赛的 noVNC 文件；新标签、静态测试或老师收到链接都不能代替上表的真人记录。

## 浏览器自动化证据与测试环境陷阱（2026-09-12）

round33 使用当前正式镜像 b6849803（键盘仍 v1）的独立座位，Chrome 经仅本地监听的 SSH
隧道连接 noVNC；未打开公网桌面、未创建 OJ 比赛或递交。实际浏览器按键验证了：

- `Numpad1/2/3/Add/4/Decimal/5` 得到 `123+4.5`；Tab 保存为 `\t`；下划线可见且字节正确。
- Shift+方向键选中 5 个字符，正常释放后两次普通点击取消选择。
- 从 GNOME 正常启动 Geany，Ctrl+Space 切换远程 IBus；输入 ASCII 拼音、空格选词，
  先后保存“你好世界”“中文输入测试”“中文输入正常”，没有用剪贴板或直接插入中文绕过输入法。
- 页面刷新并重新认证后，已保存文件仍在，继续输入 `reconnected_under_score=67` 和中文成功。
- 明确阻断一次 DOM Shift keyup，再用 `shiftKey=false` 的鼠标点击，选区恢复为 0。
  这一项属于故障注入，不冒充真人切换窗口。

本轮没有测试 NumLock 的实体状态、完整 0～9/全部运算键、Shift+Tab、本机中文输入法、
网络中断自动重连或 HTTPS/WSS。上述有限结果不能代填前面的真人表格。

两个测试工具问题必须避免：

1. `docker exec` 启动编辑器不会自动继承 GNOME 的环境。本轮最初只传入 DISPLAY 和会话总线，
   漏掉 GTK_IM_MODULE、QT_IM_MODULE、XMODIFIERS，导致中文不能正常选词。应优先从 GNOME
   启动应用；若使用脚本，必须核对这些必要字段与正常会话一致，不导出整份环境或凭据。
   本轮通过 GNOME 的 Alt+F2 重开 Geany 后完成中文测试；不能把夹具错误记作产品故障。
2. Playwright 各页面维护各自的键盘状态。在 A 页按下 Shift、切到 B 页调用 keyup，再回 A 页
   点击，仍可能发送 `shiftKey=true`。本轮确实观察到这一现象，因此不能据此宣称系统粘键。
   应记录实际 DOM 修饰键标志；故障注入须确认后续点击是 false，并明确区分正常按键与注入。
