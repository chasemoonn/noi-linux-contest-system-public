# 教师办赛指南

本页只描述老师在浏览器中的日常操作。服务器、云资源、数据库、Caddy、PM2、密钥和镜像由技术管理员维护，老师端不会提供这些控制。

## 先理解系统分工

- **OJ 系统**是比赛、报名、题目、递交、评测、成绩和源码的唯一权威来源。
- **NOI Linux 考试系统**提供统一桌面、CSP 目录、题面与辅助自测数据、程序回收、座位替换、截止冻结和安全归档。
- 北京赛制下，学生每次在网页选择 `.cpp` 递交，系统立即把该版本送到 OJ；同一题可以多次递交，以截止前最后一次网页版本为准。
- 其他地区可只使用目录交卷。系统按题判断：某题只要有网页递交，截止时就不再读取目录；该题整场没有网页递交时，才自动使用 `考号/题目名/题目名.cpp` 兜底。

## 老师只使用五个页面

| 页面 | 老师看到什么 | 主要操作 |
| --- | --- | --- |
| 比赛总览 | OJ 比赛、时间、阶段、材料、座位和送评摘要 | 读取 OJ 比赛并创建考试 |
| 比赛材料 | CSP 风格 PDF、程序名、每题 2～4 组 `.in/.out`、机器校验报告 | 预览并批准发布 |
| 学生座位 | 自动计算的正式座位与备用座位、发放状态、故障座位 | 运行教师测试、替换单个故障座位 |
| 递交与评测 | 已送评、等待、重试、失败计数和 OJ 入口 | 打开 OJ 查看实时源码与成绩 |
| 结束与归档 | 冻结、最终补交、队列、收卷凭据和安全关机状态 | 必要时提前结束或重试收卷 |

## 1. 在 OJ 创建比赛

1. 创建 **OI 赛制**比赛，设置准确的开始和截止时间。
2. 添加题目并开放报名。报名成功即视为已通过老师审核，NOI Linux 不再二次审批学生。
3. 每道题必须有唯一、符合 CSP 目录规则的程序名，例如 `apple`。
4. 比赛时间、题目或报名发生变化时，只在 OJ 修改；系统会从 OJ 同步。

## 2. 创建考试并审核材料

1. 在“比赛总览”填写 OJ 比赛编号并读取比赛。
2. 在“比赛材料”预览生成结果：
   - 一份 CSP 风格比赛 PDF；
   - 每题 2～4 组 `.in/.out` 辅助自测数据；
   - 程序名和 `freopen` 约定；
   - 机器校验报告。
3. 辅助数据只供学生本地自测，绝不进入 OJ 正式测试数据，也不计分。
4. 只有 PDF、辅助数据、OJ 私有附件和桌面文件的哈希完全一致，系统才允许老师批准。
5. 发现标题、程序名、样例或答案异常时不要批准，修正 OJ 后重新生成。

## 3. 运行教师测试并备赛

1. 在“学生座位”点击“运行教师测试并准备座位”。
2. 系统先验收第一座：桌面、PDF、辅助数据、正式答案目录、程序回收、页面和 WebSocket 全部通过后，才继续创建其余座位。
3. 正式座位数自动跟随 OJ 报名人数；备用座位始终至少为 2 个或报名人数的 10%（向上取整）。
4. 新学生报名后系统自动增加并验收座位，无需老师审批或手工扩容。
5. 不要重复点击备赛；状态为“教师测试中”或“准备座位中”时等待系统完成。

## 4. 发放与学生使用

- 到提前发放时间后，系统通过 OJ 站内消息发送学生入口。
- 学生也可以在考试入口使用自己的 OJ 账号查询座位。
- 学生桌面固定提供：比赛题面、辅助自测数据、开始答题、正式答案目录、程序回收系统和使用说明。
- 正式目录固定为 `考号/题目名/题目名.cpp`。
- 学生点击“开始答题”，系统用 Geany 打开每题唯一的 `题目名.cpp`。北京赛制在程序回收系统中选择该 `.cpp` 递交；目录赛制只需按规定保存。
- 学生只看到“已保存、等待送评、已送达、需重试”等送达状态；OI 比赛中不显示分数、测试点或排行榜。
- 老师在 OJ 查看实时提交、源码和成绩。

## 5. 比赛中

- OJ 新报名会自动触发座位增加、验收和发放。
- 单个座位故障时，在“学生座位”选择该座位并填写原因。系统会冻结旧座位、复制一致快照、撤销旧入口并发放备用位。
- 只处理单座故障，不重启全场，更不能为了桌面问题重启 OJ。
- OJ 时间是唯一时间：延后时桌面截止同步延后；提前结束时立即冻结并进入收卷。系统没有独立“加时”按钮。

## 6. 截止、归档与关机

1. 比赛服务器上的本地计时器在 OJ 截止点先暂停全部座位，再关闭桌面入口。
2. 系统按题选择最终来源：有网页递交的采用最后一次网页版本；没有网页递交的读取截止目录版本并自动提交到 OJ。
3. 所有源码 SHA、OJ 记录、收卷清单和异常都会进入不可变凭据。
4. 截止后的 30 分钟只用于补交、评测等待、核验和归档，不延长学生作答。
5. 只有待送队列为零、最终文件都有证据、入口关闭、安全组收敛后，比赛服务器才会停止计费。

## 7. 数据保存

- 正式比赛及来源不明的比赛由 OJ 原有策略保存，本系统不会自动删除。
- 专门创建的合成资格测试赛不进入长期比赛库：完成取证、关闭入口并停止云资源后，技术管理员使用 OJ 原生删除功能清理，系统必须在 30 分钟内只读核验清理结果并保留脱敏回执。不要按标题猜测或删除普通比赛。
- 本地非最终材料草稿保留 30 天。
- 最终材料与收卷证据保留 180 天。
- 清理只作用于已安全结束的本地副本；任何路径或状态不确定都会停止清理。

## 立即停止并联系技术管理员的情况

- OJ 比赛事实与系统显示不一致；
- 材料哈希、题目程序名或桌面镜像发生变化；
- 多名学生同时无法进入或截止后仍能编辑；
- 送评队列持续积压或出现永久失败；
- 入口、受管访问规则或比赛服务器不能确认关闭；
- 普通 OJ 首页、登录或评测异常；
- 页面要求老师输入云密钥、运行 SSH、修改数据库或强制关机。

不要删除容器、答案目录、收卷报告或数据库记录，也不要让学生通过反复点击制造重复提交。保留时间、座位号和页面提示，交由技术管理员使用只读诊断处理。
