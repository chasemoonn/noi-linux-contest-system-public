# 教师办赛指南

本页只描述教师在网页中的日常流程。第一次安装、服务器维护、镜像升级和故障清理由技术管理员完成；教师不需要接触 SSH、Docker、Caddy、AccessKey 或安全组。

## 赛前准备

1. 在 Hydro 创建隐藏的 OI 赛制比赛，检查开始/截止时间、题目和报名名单。
2. 在办赛后台选择比赛，确认系统读取到的时间、赛制和题目完全一致。
3. 选择提交模式：
   - `web`：学生在程序回收网页中明确提交；
   - `folder`：截止后自动收取标准答案目录；
   - `both`：推荐，网页为正式版本，没有网页版本时使用目录备份。
4. 上传题面 PDF 和可公开给学生的自测数据，检查材料清单后点击批准。
5. 选择经过本校验收的容量档并开始预热。不要在第一次使用时直接开正式比赛。

## 理解状态

| 状态 | 教师应做什么 |
| --- | --- |
| `registered` | 继续核对比赛事实和材料，不向学生发链接 |
| `preparing` | 等待逐座验收，不重复点击预热 |
| `ready` | 核对已验收座位数、名单绑定和通知状态 |
| `collecting` | 等待冻结、收卷和回传，不重新备赛 |
| `done` | 下载报告，核对 RID、入口关闭和比赛机停机 |
| `error` | 停止操作，保留页面和时间；联系管理员读取脱敏诊断 |

系统短时间把考试健康状态设为失败，可能是为了阻止在事实尚未一致时继续操作。不要通过刷新、重复预热或改比赛时间绕过它。

## 发放与开赛

- 只有 `ready` 且到达发放时间的正式座位才会收到凭据；备用位不会提前发给学生。
- 让学生从 Hydro 站内消息进入，确认准考证号与本人一致。
- 开赛前用一个普通学生账号验证：能进入桌面，但不能看到分数、测试点或排行榜。
- 让学生优先从桌面“比赛资料（从这里开始）”进入题面、自测数据和答案目录。
- 长代码优先用程序回收网页上传/下载；远程桌面剪贴板只用于短文本。

## 比赛中

- 教师可以查看座位在线状态和 Hydro 教师实时记录；不要向学生展示评测结果。
- 单个学生异常时，先记录学生、座位和时间，再使用后台提供的座位恢复/备用位操作。
- 不要修改 Hydro 比赛时间、赛制、题目或名单；这些事实已在预热前冻结。
- 不要要求管理员重启 Hydro 或整台 OJ 来修一个桌面问题。

## 截止与收卷

- 正常情况等待系统按 Hydro 截止时间自动冻结并收卷。
- “手工收答案”只用于授权的提前结束、演练或自动流程明确失效且管理员已确认的情况；它不是学生保存按钮，也不是日常加速操作。
- 进入 `collecting` 后不要再次预热、修改比赛或手工上传替代文件。
- 完成后逐项核对：
  1. 比赛状态为 `done`；
  2. 每名学生有明确最终来源、源码 SHA256、问题列表和 Hydro RID；
  3. 网页/目录选择符合本场提交模式；
  4. 待处理递交和通知均为零；
  5. 学生入口关闭，比赛机停止计费；
  6. 普通 Hydro 首页、登录和评测正常。

## 什么时候立即停止

- 比赛事实与 Hydro 不一致；
- 材料 revision、题目映射或镜像摘要改变；
- 多名学生同时断开、答案目录缺失或截止后仍能编辑；
- 入口、安全组或比赛机状态无法证明关闭；
- 普通 Hydro 首页、登录或评测异常；
- 后台要求你读取密钥、运行 SSH 命令或直接修改数据库。

停止后保留原状态和时间线，交给管理员用只读 `noictl doctor --json` 与脱敏支持包诊断。不要删除容器、目录、报告或数据库记录。
