# NOI Linux 考试系统 V1 产品契约

状态：已由产品负责人确认，进入实施阶段。

本文是 V1 的产品与验收权威。实现、页面、脚本和运维手册不得弱化这些规则；若底层 OJ、云资源或桌面环境无法证明某项规则成立，系统必须失败关闭并明确报告，而不是静默降级。

## 1. 产品定位

NOI Linux 考试系统把 OJ 系统中的一场比赛转换为标准化的远程 NOI Linux 考场。

- OJ 系统负责比赛、报名、题目、正式提交、评测、成绩、排名和赛后源码记录。
- NOI Linux 考试系统负责材料、学生桌面、答案目录、程序回收、座位生命周期、截止冻结、归档和安全关机。
- 本系统不是第二套 OJ，不维护第二套正式成绩。
- 普通老师和学生界面统一使用“OJ系统”，不暴露具体部署品牌和基础设施术语。

本项目是独立社区项目，不是 CCF、NOI 或任何 OJ 项目的官方组件。“CSP 风格”描述目录、材料和交卷习惯，不表示获得官方认证。

## 2. 唯一权威与唯一代码来源

每场比赛只允许一套权威事实：

- 比赛、名单、题目和时间以 OJ 系统为准；
- 正式代码以学生座位中的 CSP 答案目录为准；
- 正式评测、成绩和排名以 OJ 系统为准。

正式答案路径固定为：

```text
考号/
├── problem_a/
│   └── problem_a.cpp
├── problem_b/
│   └── problem_b.cpp
└── problem_c/
    └── problem_c.cpp
```

网页回收系统不得保存一套脱离该目录的源码。若未来提供上传或粘贴功能，必须先原子写入正式 `.cpp` 文件，再从该文件创建提交。

## 3. 递交与计分契约

- 学生每次点击“递交当前代码”都冻结当时的正式 `.cpp`，生成不可变递交编号，并幂等送入 OJ 系统。
- 相同递交编号的网络重试不得产生重复记录；不同的明确递交必须保留为不同记录。
- NOI Linux 对 OJ 记录只拥有“追加新提交”的权限：不得重测、覆盖、删除、替换或改写任何已有 OJ 提交及其历史。
- 故障恢复只能重放同一递交编号并取得原 RID，或在确认未创建记录后追加一个新提交；不得通过修改旧 RID 来“修复成绩”。
- 插件必须在创建 OJ 记录前持久化递交保留项，并在新记录上写入内部递交编号与负载摘要。若创建结果与 RID 日志之间发生崩溃或异常，该递交进入“状态不确定”并禁止自动重发。后台只读核对必须同时精确匹配比赛、学生、题目、语言、源码摘要、递交编号和已启动的判题任务；唯一命中才补回 RID，零个或多个候选都继续保持“待核对”。
- 学生比赛期间只能看到保存和送达状态，不得看到分数、测试点、评测结果或排行榜。
- 老师通过 OJ 系统查看实时成绩和源码，NOI Linux 老师端不复制一套成绩表。
- 最终成绩采用截止时最终代码对应的提交，而不是历史最高分。
- 截止代码与最后一次已确认提交字节相同时，只记录核验收据；不同或尚未成功提交时，创建“截止快照提交”。
- 截止前已由服务端捕获、截止后才完成技术送达的提交必须保留原捕获时间和审计证据，不得被视为学生延时作答。

如果 OJ 系统不能证明“最后一次最终代码计分”，正式比赛必须被阻断。

## 4. 材料契约

老师在 OJ 系统创建比赛后，系统生成：

- 一份 CSP 风格整场 PDF；
- 每题 2～4 组梯度辅助自测数据；
- 每组数据均为成对的 `.in/.out`。

材料流程固定为：

```text
读取 OJ 比赛
→ 生成草稿
→ 自动检查
→ 老师预览
→ 老师批准
→ 冻结版本
→ 同字节发布到 OJ 附件和学生桌面
```

AI 只能起草候选输入和版式，不是可信答案来源。每个 `.out` 必须由本地可信参考程序独立计算并通过验证。缺少可信参考程序时不得发布该题辅助 `.out`，也不得用“辅助数据不计分”作为降低正确性标准的理由。

学生材料包采用严格白名单，只允许 PDF、`.in`、`.out` 和简短说明；不得包含标程、题解、生成器、正式隐藏数据、凭证、内部 manifest 或配置。

材料批准后若 OJ 的题目、顺序、题面、程序名或文件 I/O 发生变化，材料必须标记过期。开赛后不得静默替换材料或重命名答案目录，只能发布统一、更正时间可审计的比赛通知。

## 5. 学生桌面契约

桌面固定提供：

```text
01_比赛题面.pdf
02_辅助自测数据
03_答案文件夹
04_CSP程序回收系统
05_使用说明
```

- 辅助数据只读，不进入收卷，不参与正式计分。
- 答案目录和空 `.cpp` 在发放前创建并验收。
- 删除或改名后不得自动以空文件覆盖；系统应提示并提供显式的最近安全版本恢复。
- 保存文件不等于递交；只有“已送入OJ系统”表示已取得可确认的 OJ 提交记录。
- 学生端不显示服务器、容器、网络、数据库、Token 或内部错误。

## 6. 老师端契约

老师端只有五个一级页面：

1. 比赛概览
2. 比赛材料
3. 学生与考场
4. 比赛进行中
5. 结束与归档

每个状态只突出一个主要操作。老师可以审核材料、运行教师测试、查看自动扩容、重发入口、替换故障座位、查看送达状态和打开 OJ 系统；不能操作服务器、数据库、云密钥、学生日常密码、全场重启或绕过安全条件强制关机。

第一版不提供老师实时看屏、看键盘、看终端或看未递交源码。老师只能看到在线、座位健康、最近保存、最近递交和送达状态。

## 7. 报名、座位与凭证契约

- OJ 系统报名成功即视为老师已经审核，NOI Linux 不进行第二次学生审批。
- 正式座位数自动跟随已报名学生数。
- 备用座位默认维持 `max(2, ceil(报名人数 × 10%))`。
- 新报名优先绑定已验收备用座位，再自动补充备用位；不要求老师点击扩容。
- 自动扩容不得移动、重建或中断已有学生座位。
- 资源不足时不得发送无效入口，必须保留未发放状态、自动重试并告警。
- 主要发放渠道为 OJ 系统通知；老师可重发，但默认看不到明文密码。
- 考试凭证只限本人、本场和有效时段；重发后旧凭证失效。

## 8. 时间与截止契约

- OJ 系统时间是唯一比赛时间来源，NOI Linux 不提供独立改时。
- 延长和提前结束均自动跟随；页面必须显示最后成功同步时间。
- OJ 暂时不可用时继续使用最后确认时间并明确显示“时间同步异常”，不得自行延长。
- 截止时先停止新递交和新写入，再冻结正式答案目录，最后收卷和送达。
- 截止后 30 分钟只用于送达、核验、保存、归档和关机，不是额外答题时间。
- 30 分钟后仍有未确认送达或未保存工作区时，入口保持关闭、主机进入安全等待，不得强制关机。

## 9. 故障契约

- OJ 暂时不可用时，学生可继续写、保存和生成递交快照；状态只能显示“已安全保存，等待送达”，不能虚报成功。
- 送达响应不确定时按内部递交编号和负载摘要只读消歧，不能按时间、学生或题目近似猜测，更不能盲目重试；学生仍可继续提交后续版本。
- 单座故障只替换该座位，不得重启全场；旧座位先冻结和保存，再切换到已验收备用位。
- 程序回收页面故障不得阻止截止时从正式答案目录完成最终回收。
- 递交按钮必须从固定文件描述符取得稳定源码快照；文件正在保存、路径被替换、符号链接、硬链接或读取前后元数据变化时，本次递交失败关闭并提示重试，不能送出半份或错路径代码。
- 未确认代码送达、工作区保存和入口关闭前不得宣布“安全结束”。
- 大规模身份串位、代码归属错误、截止失真或材料严重不公平时，先冻结代码并关闭相关入口，不删除数据、不强制关机。

## 10. 状态机

比赛主状态：

```text
草稿
→ 材料生成中
→ 材料待审核
→ 材料已发布
→ 考场准备中
→ 教师测试中
→ 已准备，入口关闭
→ 发放中
→ 等待开赛
→ 比赛进行中
→ 截止冻结
→ 正在回收
→ 安全等待
→ 已安全结束
→ 已归档
```

座位主状态：

```text
计划中 → 创建中 → 验收中 → 备用 → 已分配 → 已发放 → 在线 → 已冻结 → 已归档
```

递交主状态：

```text
已捕获 → 等待送达 → 正在送达 → 已确认
                    ↘ 状态不确定 → 只读核对 → 唯一确认后补回 RID
                                           ↘ 未找到/多个候选 → 保持待核对，不自动重发
```

## 11. 数据保留默认值

- OJ 提交、源码和成绩：服从 OJ 原有策略；
- 完整学生桌面工作区：30 天；
- 最终答案、材料、送达收据和操作审计：180 天；
- 临时考试凭证：比赛安全结束后立即失效；
- 普通比赛和来源不明的比赛永远不由本系统自动删除；
- 专门为资格验收创建、并由 root-only 资格会话绑定唯一比赛编号的合成测试赛，必须先完成收卷取证和资源关停，再通过 OJ 原生删除流程清理；关停核验后 30 分钟内必须取得 OJ 主机的删除核验事实。核验必须证明比赛文档、报名状态、比赛讨论、定时任务以及仍绑定该比赛的评测记录全部为零；
- 测试赛删除只清理 OJ 中的合成比赛对象，不删除题目、用户或已脱敏的资格证据；清理回执按最终证据保留 180 天。
- 运行座位：安全结束后关闭，不长期运行。

学校管理员可在赛前按制度调整期限，普通老师不能在比赛中缩短期限。

## 12. V1 明确不做

- 第二套题库、评测、成绩或排行榜；
- `web/folder/both` 让老师选择多种真相来源；
- 学生比赛中查看分数或评测结果；
- 老师批量实时监屏；
- 自动把不可信 AI 输出当作参考答案；
- 开赛后修改共享题或静默替换材料；
- 无限、无配额保护的资源扩容；
- 用全场重启解决单个学生故障；
- 未完成回收就自动关机。

## 13. 发布硬门

V1 只有在以下证据齐全时才能正式启用：

- 普通 OJ 连续性通过；
- 普通学生 OI 盲测通过；
- 每次明确递交和网络重试幂等通过；
- 截止最终代码与 OJ 最终成绩一致；
- 新报名自动扩座与失败告警通过；
- 单座故障替换通过；
- 时间延长、提前结束和同步中断通过；
- OJ 中断、递交歧义和进程重启恢复通过；
- 15 个正式座位 + 2 个备用位连续 60 分钟验收通过；
- 截止回收、30 分钟安全等待、归档和关机通过；
- 安装、升级和回滚在独立环境通过。
- 生产安装先用一个只读入口采集并封存完整备份；事务开始后，必须在任何 Hydro 或 Caddy 变更前停止并再次绑定精确旧控制器。失败回滚时旧控制器保持停止，只有 source、Hydro、Caddy、数据库、普通 OJ 与云关闭基线全部恢复并验证后才允许重新启动；启动后验失败必须再次停机。
