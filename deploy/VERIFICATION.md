# 部署验收记录模板

本文件是公开发行版的验收模板，不是任何学校当前部署已经通过的证明。复制一份到私有运维目录后填写；不要把真实域名、IP、实例 ID、安全组 ID、SSH 指纹、用户 ID、比赛 ID、评测记录 ID、座位 token、口令或 AccessKey 提交回公开仓库。

## 上游项目当前结论

- 已验证：单座位的登记、预热、桌面登录、网页递交、文件夹收卷、Hydro 送评与停机闭环曾在隔离测试场完成。
- 尚未形成通用容量承诺：官方 GNOME 桌面镜像的 15 座、30～60 分钟真实操作长稳测试仍须由每个部署环境重新执行。
- 旧轻量桌面镜像的容量数据不能外推到官方 GNOME 镜像。
- 固定 EIP 裸 HTTP 直连是短时比赛的体验优先方案；长期公网服务应在比赛机侧终止 HTTPS。

因此，首次安装只能在完成本文全部必选项后从 `Alpha` 转为“本校可用”。

## 2. 发布物与镜像

1. 从可信渠道取得源码与离线镜像包，分别核对 commit 和 SHA256。
2. 从公开 Release 声明的固定 commit 运行仓库内 `scripts/import-local-image-bundle.sh`，同时传入从同一 GitHub Release 取得的 `release-manifest.json`；不要先执行私发目录中尚未验证的导入器，不得用可变的 `latest` 代替发布标签：

   ```bash
   bash scripts/import-local-image-bundle.sh \
     --bundle-dir '/mnt/usb/noi-linux-official-2.0' \
     --release-manifest '/path/to/release-manifest.json'
   ```

3. 核对镜像标签 `org.noi.desktop.contract=finalizer-status-v1`。
4. 对解析出的不可变 image ID 运行：

   ```bash
   source_revision='<验收记录中的40位小写源码commit>'
   sudo bash deploy/verify-contest-image-local.sh \
     '<不可变镜像ID>' "${source_revision}"
   ```

5. 分别验证 `folder`、`web`、`both` 三种模式能启动，官方答案目录、只读试题材料、网页回收入口与 finalizer 状态符合约定。
6. 确认镜像和导出包不含 `.env`、私钥、`known_hosts`、数据库、日志、座位数据或现场配置。

## 3. 主机与网络基线

- Hydro、MongoDB、Caddy 管理 API 和编排器内部端口不直接暴露公网；MongoDB 只监听回环地址。
- 比赛 ECS 只使用一张专用、非托管的普通安全组，不与其他 ECS 或辅助 ENI 共用。
- 关闭态入站规则恰好是 OJ IPv4 `/32` 到 TCP 22、80 的两条 Accept；没有重复、宽端口、全协议、Drop、地址簿、端口簿或安全组引用规则。
- 学生 TCP/80 由编排器按 `ready` 生命周期管理，不在云控制台手工常开。
- SSH 严格主机校验开启；指纹来自可信控制台或云助手通道。
- 桌面网络同时满足 `Internal=true` 与 `enable_icc=false`，两个座位之间不能互访，学生容器不能访问普通互联网。
- 比赛 ECS 启用节省停机，结束后必须确认真实状态为 `Stopped`，不能把 `Stopping` 当作完成。

## 4. 只读健康检查

把文档保留示例值替换为现场值后执行：

```bash
sudo EXAM_URL='https://exam.example.test' \
  HYDRO_URL='https://oj.example.test' \
  EXPECTED_OJ_CIDR='192.0.2.10/32' \
  DESKTOP_ACCESS_MODE=direct \
  STUDENT_CIDRS='198.51.100.0/24' \
  DESKTOP_PROBE_BASE_URL='http://203.0.113.20' \
  DESKTOP_PROBE_TOKEN='<已验收座位token>' \
  bash deploy/health-check.sh
```

要求：

- 所有示例地址已替换，最终 `fail=0`。
- 若学生来源不得不用 `0.0.0.0/0`，必须另设 `CONFIRM_PUBLIC_DESKTOP_CIDR=YES`，记录批准人，并限制开放时段。
- 活动 Caddy 配置与磁盘完整配置的规范化指纹一致。
- 公网 Hydro 的 `/orchestrator/submit*` 返回 404，本机 Hydro 无 token 请求返回 403。
- 编排器 `/healthz` 返回 `ok=true`，三份插件幂等状态文件存在、可写且权限为 `0600`。
- 比赛关闭时 OJ `/s/*` 返回 503，EIP 不接受新连接；比赛开放时有效页面 200、WebSocket 101、未知 token 404。

## 5. 单座位真实闭环

在隔离的短时 OI 测试比赛中完成以下动作；不得借用或修改现有学生账号和正式题目：

1. 创建专用测试用户、私有测试题和短时比赛，只登记一名选手。
2. 预热一个正式座位和至少一个备用座位，核对镜像不可变 ID 与材料摘要。
3. 在 T-5 前确认学生查不到密码；T-5 时确认 Hydro 原生消息包含可点击入口而不是裸 Markdown。
4. 从学生桌面分别完成两次网页递交，确认两次明确点击创建不同评测记录，同一次网络重试不会重复创建。
5. 在官方答案目录保存另一题，仅通过文件夹路径收卷。
6. 在 `both` 模式确认网页版本优先；没有网页版本时才选择文件夹版本。
7. 用教师账号确认评测记录从 Waiting 到达终态；用普通学生账号确认比赛中看不到分数、测试点或排行榜。
8. 故意提交一次缺少文件 I/O 的代码，确认静态规则强制零分；再提交合规版本，确认最终评测正确。
9. 截止后确认不能创建新的有效提交，网页版本复用已有记录，五份收卷报告齐全。
10. 删除全部测试用户、题目、比赛、评测记录、座位、临时插件和原始测试数据，并再次执行赛后健康检查。

## 6. 截止、直连与故障恢复

必须逐项保留时间戳证据：

- `ready` 前学生 TCP/80 不存在；`ready` 后仅增加一条带完整 owner 的学生规则。
- 高速 EIP 页面与 WebSocket 分别为 200/101；HTTPS 兼容入口也为 200/101。
- ECS 上的持久化 freeze timer 在 Hydro 截止点先暂停全部座位，再停止本机 nginx；这才是精确文件截止证据。
- 截止、收卷、手动关机和错误路径均撤销学生规则；阿里云控制面异常时仍由本机 timer 关闭数据面。
- 编排服务重启后能恢复对账；安全组规则或 EIP 漂移时失败关闭。
- 故障替换会先暂停旧座位并复制一致快照；网关或数据库提交失败时旧座位可恢复。
- 收卷失败保留答案与 outbox，可使用原幂等键重试，不通过重新备赛清空状态。

## 7. 15 座长稳与容量签字

1. 同时启动 15 个正式座位和计划中的备用座位。

## 8. Go / No-Go

只有同时满足以下条件才允许正式发放座位：

- 本文第 2～7 节全部通过，且证据来自当前源码、当前镜像和当前云环境。
- 真实 15 座长稳通过；若只验证更少人数，正式人数不得超过已验证值。
- 赛前健康检查 `fail=0`，没有未解释的 Caddy、EIP、安全组或镜像漂移。
- 已演练收卷失败重试、故障座位替换、截止失败关闭和人工 StopCharging 兜底。
- 已明确数据保存期限、座位 CSV 保管人、紧急联系人与人工裁决流程。
