# V1 验收与容量签字

源码测试通过不等于系统可办赛。每个部署必须依次通过静态验收、单座真人闭环、故障恢复、完整比赛和目标容量长稳测试。

## 1. 固定验收身份

每份报告必须记录且不得混用：

- Git commit；
- 控制面镜像 ID、Hydro 插件 SHA、桌面镜像不可变 ID；
- OJ 版本、Node 版本、实例规格、地域和网络 profile；
- 比赛 PDF 与辅助数据包 SHA；
- 测试日期、执行人和独立复核人。

任一关键摘要、规格、数据路径或网络拓扑变化都会使容量证据失效。

## 2. 自动化门

Linux CI 必须全部通过：

```bash
python -m compileall -q orchestrator
(cd orchestrator && python -m unittest discover -s tests -v)
node --check hydro-plugin-orchestrator/index.js
node --test hydro-plugin-orchestrator/tests/*.test.js
bash -n deploy/*.sh scripts/*.sh
python scripts/build_demo.py --check
python scripts/check_public_release.py
```

此外必须证明：

- 教师端只有五个产品页面且没有基础设施控制；
- 旧 `web/folder/both` 数据值不能改变“逐题网页优先、目录兜底”的固定规则；
- 材料发布回执、递交幂等、截止补交、安全关机、审计、重启恢复和 30/180 天清理都有机器测试；
- 清理与失败恢复不会修改 OJ 权威数据。
- Hydro 插件只有一个 `RecordModel.add` 追加入口，不包含重测、更新、替换、删除或 history 写入路径；控制面也不调用 OJ record mutation API。
- 正式源码在稳定文件描述符快照中读取；并发保存、路径替换、符号链接、硬链接和不完整读取全部失败关闭。
- 注入 `RecordModel.add` 返回前异常，证明已持久化的 `reserved` 项会阻断后续自动重发，OJ 新建调用总数保持一次。

## 3. 单座真人闭环

用一名普通学生和一名老师完成：

1. OJ 建立隐藏 OI 比赛并报名；
2. 生成 CSP PDF 和每题 2～4 组辅助 `.in/.out`，老师批准；
3. 第一座教师测试通过；
4. 学生收到入口，进入桌面；
5. 检查固定五个桌面对象；
6. 在 `考号/题目名/题目名.cpp` 编写带 `freopen` 的程序；
7. 对 `apple` 网页递交两次，再修改目录但不网页递交；确认 OJ 保留两条网页记录且截止仍选最后一次网页版本；
8. 对 `banana` 整场不网页递交，只修改正式目录；确认截止只为该题创建一次目录兜底提交；
9. 核对 OJ 源码 SHA、收卷 SHA 和桌面最终 SHA 完全一致；
10. 核对队列清零、入口关闭、服务器停止计费和普通 OJ 正常。

## 4. 故障恢复矩阵

至少注入并通过：

| 故障 | 必须结果 |
| --- | --- |
| 材料生成中进程重启 | 任务变为 interrupted，未发布半成品 |
| 备赛中进程重启 | 比赛变为 error，入口保持关闭 |
| OJ 送评超时 | 不盲目重发；按幂等 ID 消歧 |
| 单座容器崩溃 | 只替换该座，答案一致，不重启 OJ |
| 控制面在截止点失联 | 比赛机 timer 仍暂停座位并关闭入口 |
| 收卷中进程重启 | 从冻结证据幂等恢复，不产生重复 OJ 记录 |
| 云 API 短暂失败 | 入口失败关闭，状态可见，恢复后重试 |
| 本地清理遇到符号链接/越界 | 不删除，记录错误，比赛数据保留 |

## 5. 报名与时间变化

- 开赛前、开赛后各新增一名已报名学生，验证自动扩座、验收和发放，无老师二次审核。
- 将 OJ 截止延后，验证本地 timer 原子更新且旧 timer 不再生效。
- 将 OJ 截止提前，验证立即冻结，学生不能继续写入。
- 验证 30 分钟仅用于送达和归档，学生端没有加时。

## 6. 目标容量长稳

当前目标为 15 个正式座位 + 2 个备用座位。必须使用真实 GNOME 桌面连续运行至少 60 分钟：

- 15 名模拟学生持续编辑、编译、运行辅助数据和滚动桌面；
- 分阶段建立 WebSocket，避免把同一测试机出口当作真实校园网络；
- 每人至少两次正式递交；
- 随机断开并重连；
- 至少执行一次带答案迁移的故障座位替换；
- 截止时同时冻结 15 座并完成最终补交；
- 17 个容器全部可验收、无 OOM、无 restart、无答案串位；
- 普通 OJ 首页、登录和评测全程正常。

报告至少包含 CPU、内存、load、磁盘、网络、容器 restart/OOM、页面与 WS 成功率、递交延迟、收卷耗时和普通 OJ 探针。

## 7. 签字规则

只有以下全部满足才可将 profile 标为“已认证容量”：

- 自动化门全绿；
- 单座真人闭环全绿；
- 故障矩阵全绿；
- 时间与报名变化全绿；
- 15+2 长稳全绿；
- 执行人与独立复核人签字；
- 报告固定所有版本、镜像和规格。

否则只能声称相应能力“已实现”或“单座已验证”，不能声称该环境可可靠承载 15 人。
