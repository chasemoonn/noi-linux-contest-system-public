# 架构与性能基线（≤15 人）

更新日期：2026-08-09

## 决策

正式模拟赛继续使用“一名学生一个容器”，不改为宿主机多 Linux 账号。

容器不是完整虚拟机。15 个座位共享宿主机内核和镜像只读层；真正占用资源的是每名学生各自的 GNOME、TigerVNC、浏览器和 IDE。改成宿主机账号后，这 15 套图形会话仍然存在，但文件、进程、网络、资源限制和单座位恢复都要重新实现。

宿主机多账号只适合作为可信机房的低隔离实验模式，不作为正式比赛模式。若要达到当前容器方案的边界，至少还需要 systemd slices、PID/内存/CPU 限制、磁盘配额、每用户网络策略、`/proc` 隐藏、AppArmor/SELinux、会话清理和可重复的主目录恢复；这实际上是在自行重做容器管理。

## 座位池生命周期

容量分成两个边界：`seat_pool_maximum` 是正式参赛人数，`seat_pool_total_maximum` 是正式座位加备用位的容器总数。默认按 15 名学生和 2 个备用位设计；备用位只接管故障，不增加比赛人数。

1. 教师批准题面和自测材料后，系统可在 Hydro 名单为空时预热 `最大人数 + 备用位`。每个槽位固定使用同一镜像摘要和材料摘要，并独立检查 GNOME、noVNC、PDF、自测数据和答案挂载。
2. 学生报名只把 `uid` 绑定到已验收槽位，不重建 Docker。默认到 T-5 才把 `reserved` 变为 `released`，由持久化通知队列调用 Hydro 原生结构化消息；消息气泡不依赖 Markdown 渲染。
3. 现场扩容只向状态机追加新槽位。全部新增容器通过验收并完成 nginx 可回滚切换后，SQLite 才以 revision CAS 一次发布；任一失败仅删除新增槽位，旧学生链接和 `uid → slot` 不变。
4. 故障替换先暂停仍在运行的旧容器，复制一致答案快照到已验收备用位，再原子撤销旧资源并换绑凭据。网关或数据库提交失败时先恢复旧网关，再恢复由本次操作暂停的原容器；原本已经 paused/exited 的故障容器不会被擅自启动。
5. 截止时比赛 ECS 的持久化 systemd timer 先暂停全部座位、再停止本机 nginx 桌面入口；控制面随后收卷。冻结优先，避免 nginx 优雅停机被长连接拖延；若停 nginx 失败，systemd 会在座位保持暂停的情况下重试。即使 OJ/编排器当时失联，既有 WebSocket 也会由本机关闭。桌面状态与 SQLite 状态均保留到 Hydro 回传完成，收卷失败只允许重试收卷。

这套设计把昂贵、易失败的桌面启动移到赛前，把开赛附近的操作缩小为数据库绑定和消息发送。15 人规模无需 Kubernetes；容器只读镜像层共享，按座位独立的写层、答案 bind mount 和故障域才是需要保留的部分。

## 材料与评测控制面

- 非文件读写题不在共享题上原地改配置。Hydro 插件先生成本场私有克隆预检，教师批准后再创建克隆并更新本场题目映射；正式输入只计算规范化 SHA256，隐藏数据内容不离开 Hydro。
- AI 只接收清理后的题面快照和禁止重复的 hash，起草 CSP 风格题面及自测输入。逐题可信 validator 检查输入，逐题可信 oracle 在本地独立运行两次生成一致输出。工具目录以只读卷挂载，AI key 只从运行时环境变量读取。
- PDF、测试数据包、manifest 和 validation report 是一个不可变 revision。教师批准前不能成为活动材料，也不能预热桌面。
- V1 只有一个正式答案目录。每次明确递交都重新读取该目录中的当前文件，先落 SQLite outbox，再实时建立 OJ RID；截止冻结后按源码 SHA 核对最后已确认版本，必要时补交最终文件。教师可在 OJ 监控，OI 赛制普通学生继续盲测。
- 有效截止按选手个人窗口校验 `accepted_at_ms`，截止点为开区间终点。截止前已可靠入队的请求可在截止后完成送评，相同幂等键返回原 RID；截止后新请求拒绝。网页路径和文件夹 timer 共同保证严格截止。

## 16C64G / 15 座位起始档

| 项目 | 基线 | 目的 |
| --- | ---: | --- |
| 分辨率 | 1366×768 | 保持可用画面并控制编码像素数 |
| TigerVNC 帧率上限 | 30 | 编程桌面不需要 60 帧，避免无效编码 |
| noVNC quality | 9 | 优先保证代码文字清晰；压测确认出口带宽后再决定是否下调 |
| noVNC compression | 2 | 优先降低服务器编码 CPU |
| CPU 上限 | 1.5 核/座位 | 允许桌面短时突发，同时限制死循环影响 |
| 内存上限 | 2.5 GiB/座位 | 容纳 GNOME、Firefox 和 IDE |
| swap | 禁用（memory-swap=memory） | 避免交互桌面因换页出现长停顿 |
| PID 上限 | 1024 | 容纳完整桌面，同时防止 fork bomb |
| `/dev/shm` | 1 GiB | 浏览器与桌面共享内存 |

这些数值是压测起点，不是容量承诺。比赛前必须用实际杭州链路做 15 路测试。

## 问题定位顺序

1. 宿主 CPU 持续接近满载：先看 Xtigervnc、gnome-shell 和学生程序占用；保持 24～30 帧、低压缩，禁止后台更新和索引。
2. 公网出口接近上限：先记录每座位峰值 Mbps；确有带宽瓶颈时再小步提高 compression，最后才降低 quality。
3. CPU、带宽都有余量但操作仍慢：检查学生到服务器的 RTT、丢包、WebSocket 重连及是否仍经香港/其他中转。
4. 个别座位慢：检查该容器 CPU、内存、OOM、PID 数、GNOME 会话和 VNC 日志，优先单座位恢复，不重启全场。

## 赛前 15 路验收

- 15 个座位使用同一个 `noi-linux-official:2.0` 镜像摘要。
- 连续操作 30～60 分钟，无资料文件缺失和 `.desktop` 打开为文本。
- 每个座位的 PDF、自测数据、答案目录、网页入口完整率为 100%。
- `_{}[]\\|\"'<>` 等编程字符和 Ctrl+Space 中英文切换全部通过。
- 含中文、超过 10 KiB、末尾无换行的 UTF-8/LF 源码上传后再下载，字节 SHA256 完全一致；另用 BOM、CRLF 和 GB18030 文件确认下载结果等于预期的 UTF-8/LF 规范化内容并可正常编译。
- 一个学生运行死循环时，其他座位仍可交互；停止该容器即可恢复。
- 一个座位重启后答案目录仍存在且可写。
- 记录宿主 CPU/内存、每容器 CPU/内存、出口 Mbps、RTT、丢包、断线重连次数和键到画面的 p95 延迟。

## 后续可做的 A/B 测试

若完成上述优化后 noVNC 仍不能满足体验，只替换远程显示层做 3 座位 A/B 测试：TigerVNC/noVNC 对比 KasmVNC，或 Guacamole+xrdp。容器隔离、官方 NOI Linux 根文件系统、答案挂载和编排接口保持不变。

不建议直接改成 Kubernetes，也不建议先改为宿主机多账号；两者都不会减少每名学生一套图形桌面的核心成本。

## 桌面网络路径

当前短时模拟赛的正式桌面数据路径是学生浏览器直达杭州比赛 ECS 固定 EIP 的 HTTP/80，不再经 OJ/香港转发 noVNC WebSocket。Hydro 消息仍使用 allowlist 内的 HTTPS 控制面链接；编排器校验比赛和座位状态后返回启动页，默认按钮进入 EIP 高速入口，备用按钮进入明确标注“较慢”的 OJ HTTPS 兼容入口。持续的页面、键鼠、图像和 WebSocket 默认全部走 EIP；兼容入口仅用于直连受校园网络限制或浏览器拦截时应急。两条入口共享同一 `ready`、截止、收卷和失败关闭生命周期。

学生来源未知时临时规则可配置 `0.0.0.0/0`，但只能存在于唯一有效 `ready` 场次。比赛机必须使用主网卡专属的普通 basic 安全组且不能挂任何辅助 ENI；编排器会分页证明该组没有被其他 ECS/辅助 ENI 共享、目标实例也没有使用其他安全组的辅助 ENI，并对入站规则执行精确白名单。关闭态只允许唯一 OJ IPv4 `/32` 的 TCP 22/80，开放态只多一条带 owner/instance 标识的学生 TCP/80；Drop、数字协议、地址簿/端口簿或任何其他/重复入站规则都会阻断开放，避免 OJ 探针能通而普通学生被高优先级 Drop 拦截的假绿。

编排器启动恢复和每 5 秒对账会清除失去所有权或已过期的受管规则，收卷、手动关机、服务正常退出和错误路径均撤销；若退出时无法确认撤销，则停比赛 VM 兜底，OJ 主机不受影响。OJ `/32` 的 TCP 22/80 管理与回退规则不进入删除集合。云安全组是有状态的，删除规则后既有 WebSocket 可能最长保留约 910 秒，且阿里云规则没有服务端 TTL；因此安全组只承担“不再接受新入站”。精确截止由比赛 ECS 的持久化 systemd timer 先暂停全部座位（不可延迟的文件截止屏障）、再停止 nginx（切断本机 TCP/80 和既有 WebSocket）保证；若控制面跨过截止仍失联，云规则在其恢复后撤销，但数据面已经关闭且 SSH 仍可用于收卷。

这项方案接受浏览器 HTTP 警告和链路明文风险来换取临时比赛的交互体验。长期产品化仍应把专用域名直接解析到杭州 EIP，在比赛 ECS 本机终止 HTTPS；不要恢复跨地域 noVNC 中转。
