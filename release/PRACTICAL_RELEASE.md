# NOI Linux 普通比赛可用版

本页记录当前版本面向日常集训、模拟赛和复赛准备的实际交付口径。它强调“能稳定办一场普通比赛”，不把长时间压力、断电恢复或复杂灾备作为本次上线前置条件。

## 交付结论

当前版本可进入普通比赛部署，建议单场不超过 **15 个正式座位 + 2 个备用座位**。首次在新服务器安装后，管理员仍应先完成一座教师测试，再向学生开放入口。

已经验证的主流程：

- 从 OJ 读取比赛、题目、时间和报名名单；
- 生成 CSP 风格 PDF、每题 2～4 组不计分的 `.in/.out` 辅助数据；
- 创建并发放 NOI Linux 座位；
- 15 个浏览器页面和 WebSocket 同时建立连接；
- 学生在正式 CSP 目录编写、编译和自测；
- 程序回收页面读取正式目录并把源码递交到 OJ；
- OJ 生成真实递交记录，老师可查看源码和评测；
- 截止时冻结最终文件、补交、生成收卷凭据、关闭入口并停止比赛服务器；
- 普通 OJ 首页、登录、评测准备服务和四个基础进程在资格流程中保持正常。

单座九阶段资格证据已经通过仓库官方校验器，覆盖材料、桌面、编译、手动递交、截止递交、OJ 记录、收卷、关机和测试赛清理。容量演练还验证了 15 个座位同时连接以及真实网页递交。

## 本次不作为上线前置的项目

- 60 分钟持续满载压测；
- 宿主机突然断电和磁盘损坏演练；
- 多机房、双控制器和自动灾备切换；
- 所有极端并发、恶意本机用户和罕见网络时序。

这些项目可以后续补做，但不阻塞低频普通比赛使用。当前版本不应因此宣传为高可用或无人值守的企业级平台。

## 每场比赛的最短操作流程

1. 老师在 OJ 创建 OI 比赛，设置题目、开始/结束时间并开放报名。
2. 在 NOI Linux 控制面读取比赛，检查并批准 PDF、程序名和辅助数据。
3. 点击“运行教师测试并准备座位”，等待状态变为 `ready`。
4. 用教师测试座位打开桌面，确认 PDF、答案目录、编译和程序回收页面可用。
5. 到发放时间后检查学生通知和座位数量；新增报名由系统自动增加座位。
6. 比赛中老师主要在 OJ 查看递交、源码和成绩；单座故障只替换该座位。
7. 到 OJ 截止时间后等待系统收卷，确认入口关闭、递交队列为零、比赛服务器已停止。

老师的详细页面说明见 `docs/TEACHER_GUIDE.md`，管理员的单场检查见 `deploy/CONTEST_RUNBOOK.md`。

## 比赛前必须保留的四个检查

以下检查很短，不应省略：

1. OJ 首页、登录页和准备服务健康；
2. 控制器健康，递交与通知队列没有积压；
3. 一座教师测试能打开桌面、编译并完成一次测试递交；
4. 没有活动比赛时学生入口关闭，比赛服务器处于停止状态。

任一项失败时，不向学生发放入口；先停用 NOI Linux，普通 OJ 可继续独立使用。

## 简单回退

部署时必须保留安装前的控制器容器/镜像、配置备份和普通 OJ 基线。常见故障的回退原则是：

1. 关闭 NOI Linux 学生入口并停止比赛服务器；
2. 停止当前控制器，恢复上一版容器/镜像和配置；
3. 不重启 Hydro、Caddy、MongoDB 或整台 OJ 主机；
4. 重新检查 OJ 首页、登录页和准备服务。

如果来不及修复，直接停用 NOI Linux，学生仍可回到 OJ 参加普通网页比赛。

## 已知边界

- 容量演练宿主机曾在预定结束前被外部终止，因此该次 15 座演练不用于证明自动收卷；自动收卷与关机采用此前已完整通过的单座九阶段资格证据。
- 集中在一台教师虚拟机同时渲染 15 个桌面会出现帧测量超时；15 个页面和 WebSocket 均能同时建立。真实学生分散在各自浏览器，当前按普通比赛口径接受。
- 当前交付仍应在独立测试机安装后先跑一座教师测试，不直接在活动比赛期间升级。
